# Chat channels

Lost Tales provides five player-conversation channels while leaving commands, server messages, death messages, and other mods' chat components on Minecraft's normal paths.

- **All** is global in-character conversation.
- **Proximity** is in-character conversation delivered only to players in the sender's dimension and within the server's configured radius.
- **Party** is in-character conversation delivered only to online members of the sender's current Lost Tales party. It is unavailable without a valid party.
- **Faction** is in-character conversation delivered only to online characters whose configured faction matches the sender's active character. It is unavailable without a valid active-character faction.
- **OOC** is global out-of-character conversation and uses the Minecraft account name and account skin.

In-character messages require an active role-playing character and snapshot its name and skin when the server accepts the message, so existing history does not change after a character switch. The current LOTR title and the exact color exposed by LOTR's faction explorer are snapshotted presentation details. Players without an active character can use OOC with their account identity and skin, but cannot send to All or another in-character channel.

LOTR NPC speech that would print as a plain yellow chat line is restyled on the client into the same presentation: an NPC message shows the Proximity channel when the NPC is within the server's proximity radius (All otherwise), a timestamp, the NPC's rendered skin as its head icon, and a honey-coloured name. This is purely visual — a coremod hook replaces only the final chat print in LOTR's speech packet handler, so speech content, recipients, NPC behaviour, and LOTR's immersive floating speech are untouched, and any failure falls back to LOTR's original line. It can be disabled with `client.enableNpcChatStyling`.

Chat lines are spaced eleven pixels apart (vanilla uses nine), each line's backdrop filling the full stride so neighbouring bands connect seamlessly; the extra height is what gives inline emotes and head icons their room. Channel colours come from the shared palette — All is meadow green, Proximity teal, Party seafoam, OOC orchid — except Faction, which shows the sender's exact LOTR faction colour; the `:` after the channel name and the channel indicator share the channel's colour, and timestamps use the palette's plum gray in italics. Clicking a message's head icon fills the input with the same `/msg AccountName ` reply as clicking the name.

Players can style their own messages with `&`-formatting codes (`&6gold`, `&lbold`, `&r` reset — the usual Minecraft codes with `&` in place of the untypable section sign). Translation happens on the receiving client at display time; the wire format, copied text, and history keep the ampersand form. Mentioning someone with `@Name` — their account name or active character name, case-insensitive with word boundaries — highlights the message's backdrop in the palette's wine for the mentioned player and plays a ping sound on arrival (`client.chatPingSound`, the note-block pling by default; self-pings work). Typing `@` shows a completion list of online players plus your own identities, filtered live and accepted by click, Up/Down, Tab, or Enter, exactly like the emote completions. Mention detection is purely client-side presentation (each client checks its own names), and `client.enableChatPings` turns the whole feature off.

Messages use the compact form `All: [HH:mm] | <HEAD Title CharacterName> Message`. Channel names use normal title casing, and Faction uses the active faction's exact color. The invisible head marker reserves exactly the icon width; there is no extra visible padding inside the brackets, and both brackets use the character name's exact RGB color. Clicking the displayed name fills the chat input with `/msg AccountName `, including for character channels where the visible role-play name differs from the Minecraft account name. While chat is open, hovering the rendered head or name shows a bounded player card. It uses the message's snapshotted identity plus public active-character appearance data already synchronized to the client; unavailable or stale character details are omitted.

The selected channel appears beside the chat input as `[All]`, `[Party]`, `[Faction]`, `[Proximity]`, or `[OOC]`. Without an active character, only OOC is offered. Party and Faction are omitted when the active character cannot use them. With an empty input, `TAB` cycles available channels. With text or a command present, Minecraft's normal autocomplete remains active. Clicking the indicator opens a compact selector upward. Right-clicking a visible message copies only its message body and briefly confirms the action. Chat and the other Minecraft GUI screens use the same Lost Tales cursor as the LOTR map.

`chat.proximityRadius` is a server-authoritative gameplay setting. Timestamp visibility, the emote toggle, and the message, input-bar, and selector animation settings are client presentation preferences under the `client` category. A new message eases upward and slides in from the left with a short fade, briefly overshooting its resting position to the right before settling; the input bar enters with restrained overshoot. Disabling animation does not alter layout, routing, history, or command behavior. Chat surfaces — the message backdrop and the input bar included — use the palette's plum black (`#2d1e2f`) at half opacity; the message backdrop fades to transparent over its final third, while the input bar is solid across its width.

## Emotes

Player channel messages may contain emote shortcodes such as `:smile:`. They travel as ordinary message text — the server, the packets, and copied messages always carry the canonical `:name:` form — and each receiving client with `client.enableChatEmojis` enabled renders recognized shortcodes as inline 10×10 sprites that participate in normal layout and line wrapping. Unknown, incomplete, or malformed values (`:does_not_exist:`, `:sm`, a lone `:`) stay literal text, so mixed setups degrade to readable shortcodes. Disabling the toggle also shows shortcodes as plain text.

A small smiley button at the right end of the chat input toggles the emote picker; selecting an emote inserts its shortcode at the current cursor position without disturbing the rest of the input, and the panel stays open for further picks. The picker has a search field that filters by name, a Favorites row (right-click any cell to toggle a favorite, marked with a small gold dot), a Frequently Used row ranked by how often each emote has been sent, and the full grid; hovering a cell shows its shortcode as a tooltip. Favorites and usage counts are per-installation client preferences stored in `config/losttales/chat_emotes.txt` — nothing is synchronized. The button and panels are positioned from the live chat geometry, so GUI scale and resolution changes are handled.

Typing an unclosed shortcode such as `:fl` shows a completion list above the input, filtered live as more characters are typed. Click a row or use Up/Down plus Tab or Enter to complete it (Enter never sends the message while the list is open); Escape hides the list without closing chat. Completions never anchor on the closing colon of an already-completed emote, and commands never trigger the list.

The canonical registry is the `ChatEmoji` enum (`chat/emoji/`), which doubles as the picker order. Adding an emote means drawing it into a free 10×10 cell of `textures/gui/emotes.png` (11-pixel stride, 1-pixel gutters) and adding one enum constant naming that cell; `ChatEmojiSheetTest` fails the build if the sheet and registry disagree. Shortcodes are lowercase `a–z`, `0–9`, `_` and are wire format: never rename or reuse one. `ChatEmoji` and the parser are deliberately free of client classes; sprites, markers, the picker, and rendering live in client-only code.
