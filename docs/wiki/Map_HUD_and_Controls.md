# Map, HUD, controls, and third-person camera

Lost Tales adds client displays on top of server-owned quest, party, combat, and container state. Display settings are local to each client; the server decides what information the client is allowed to receive.

## Default controls

| Action | Default input |
| --- | --- |
| Open character menu | Caps Lock |
| Open quest journal | J |
| Open / close Middle-earth map | M |
| Toggle Lost Tales HUD | H |
| Open HUD placement editor | Left Alt + H |
| Quick-loot use | R |
| Modifier | Left Alt |
| Swap camera shoulder | C |
| Create personal waypoint (map only) | C |
| Current location (map only) | R |
| Find location (map only) | F |
| Toggle target lock | Middle mouse |
| Cycle target left or right | Unbound |

All bindings can be changed in Minecraft's Controls menu. The Map binding opens the Lost Tales Middle-earth map from gameplay and closes it from the map screen. While looking at a supported quick-loot container, hold the Modifier key and use the mouse wheel to change the selected row. Press the Use key to ask the server to remove the selected full stack and drop it above the container.

## HUD

The client can display:

- a compass with discovered markers, eligible LOTR waypoints, hostile combat contacts, party members, and the party go-here marker;
- a four-member party status panel;
- a quick-loot container preview;
- pinned quest objectives;
- quest notification toasts;
- location-discovery banners and area-name notices;
- discovered and active quest markers in the world.

Open the placement editor, click a HUD box to select it, and drag it. Panels cannot cross the four-pixel screen margin. A panel snaps when its center comes within six scaled pixels of the horizontal or vertical screen axis. The background uses a ten-pixel grid with stronger fifty-pixel divisions. Press Escape to save and return. A selected panel can also be nudged one pixel with the arrow keys, or ten pixels while holding the Modifier key.

The editor includes every fixed-position Lost Tales panel: Compass, Party, Quick Loot, Quest Tracker, Quest Notifications, Location Discovery, and Area Name. World-space markers, the aiming reticle, projectile trajectory, and full-screen visual effects are not placement panels because their screen position is derived from the world, crosshair, or full display.

HUD positions use bounded percentage offsets. Quick Loot uses the full screen and existing right-side positions migrate automatically. Built-in placement presets remain available through configuration and `/losttales hud`: `default`, `lotr-safe`, `compact`, and `minimal`; `custom` preserves manual positions.

The `/losttales hud` operator helper only changes settings in an integrated server, where client and server share one process. A dedicated server refuses the command because it cannot edit a remote client's HUD configuration.

## Map markers and waypoints

The bundled resources define 291 static map markers across cities, towns, settlements, forts, camps, caves, and LOTR waypoint mappings. A marker can be hidden until discovered, pinned, shown on the compass, linked to quest stages, or used to unlock an associated public LOTR waypoint.

Lost Tales adds its overlay to LOTR's Middle-earth map and uses the normal LOTR biome or faction fast-travel region whenever possible. Fast travel remains subject to LOTR's own region and waypoint rules. Combat markers are transient, server-approved, and never saved as discovered locations.

Every bundled LOTR waypoint marker uses the same discovery and visibility rules, including the Sun Elves, Moon Elves, Odane, and Orocarni. Entering the biome associated with a waypoint unlocks its LOTR fast-travel region and reveals the marker on the map. Moving close enough discovers the exact location and stores that state on the server. Added faction waypoints use their territory's existing biome region; Odane uses its generated Odane biome region.

Markers whose icons overlap are drawn as one stack: a leading marker with up to two companions fanned out behind it, and a "+X more" label for anything the fan cannot show. Only markers of the same kind ever share a stack, so a quest objective, a party Go Here marker, a player waystone and a location never merge into each other. Some kinds never stack at all: a player's own and shared waypoints, quest objectives, and combat contacts are each placed or reported for their own reason and stay individually readable at every zoom.

A marker joins a stack by coming to rest on one particular marker, and that is what holds it: it stays while it still overlaps that marker and leaves the moment it does not, taking anything resting on it along. Zooming back in therefore takes a stack apart in the same order and at the same points that zooming out put it together. Whole stacks merge by their leading markers meeting, so a stack never reaches further than the icon it is drawn as, however many markers it has gathered.

The map zooms smoothly rather than in fixed steps, and grouping follows the icons as they are actually drawn: markers merge at the moment they overlap and separate at the moment they stop, instead of jumping to whatever the next zoom level would have looked like. The wide limit is a readable regional view rather than a postage-stamp view of the entire printed map. The close limit enlarges the bounded 33-chunk-diameter terrain capture region to roughly 2510 GUI pixels across, enough to cover a large display when all of those chunks are already known to the client.

Every leading marker is drawn above every fan, so the markers meant to be read are never buried behind another stack's background sprites, and hover and click ownership follow that same order. Marker names sit above the artwork and the "+X more" summary below it, both the same distance out. Tooltips follow the pointer only: a click never leaves one behind. The map draws its own hover cards in the shared HUD colours rather than LOTR's, so a marker can carry a description as well as a name, and only the icon grows when it is highlighted.

Left-clicking empty map places the party Go Here marker. Once one exists it is shared with the party and is what everyone is walking towards, so moving it is asked for rather than assumed: clicking empty map again opens a confirmation offering Move It, Leave It or Remove It, and clicking the marker itself opens the same question without a destination to move to. Removing the marker therefore always takes an explicit answer. Placing it from the fast-travel popup's Place Marker action repositions it immediately, because that click already named the destination. The marker belongs to the player's active roleplaying character and is shared with their party; a player who has no character selected owns it themselves instead, so the map is usable before a character exists. The server resolves that owner independently for every request, and a character-less player is sent nothing but their own marker. Placement happens on release and only when the pointer has not moved, so dragging the map or clicking a marker never drops one by accident.

The map has one camera, and every action that moves it shares that camera. Left-clicking a stack frames it: the camera pans so the marker the stack is drawn as sits at the centre of the map, and zooms only as far as the same grouping rule says its members need to stand apart. Once the markers stand apart, clicking one reaches the marker itself. Opening a fast-travel confirmation frames its destination the same way, but at an anchor worked out from the popup's own layout: the marker comes to rest centred just above the panel, at any resolution or GUI scale, and the popup leaves an opening in the shade around it so it stays as readable as it was on the open map. Both movements pan and zoom on one eased progress and follow a path that leads along the axis the camera is mostly travelling on, so a movement downward sets off downward rather than sliding along a ruler. A second click retargets the movement from the point the camera is framing at that moment rather than restarting it. The map holds still while a popup is open, except for a focus the popup itself asked for.

Closing the map does not throw the view away. Where the camera was, how far it was zoomed, and how far it was turned and leaned all come back exactly as they were left, without an animation to sit through — closing the map to walk a few paces and opening it again should not cost you your place on it. The drags that bought the turn and the lean are kept with them, so the next gesture continues the last one rather than starting again from square. The first time the map is opened it still centres on the player, and `R` recentres it at any time. The view is held only for as long as the client is connected: it is a view of one world's map and is dropped on leaving, along with everything else the map learned about that world.

Holding the right mouse button and dragging turns and leans the map. Sideways turns it, up to 33.75° either way; only horizontal movement counts, so a steep diagonal barely turns it. The turn is not linear: square has a detent, so leaving true north takes a deliberate movement and returning lands exactly on it, and resistance grows steeply with the angle — the last couple of degrees cost several times the drag the first ones did. That stiffness is only there on the way out. Reversing a drag back towards square releases it immediately and the map comes back at one steady rate however far out it was, so an angle you have just pushed to its limit is not one you then have to fight your way out of. Dragging down in the same gesture lowers the eye towards the sheet, through the same drag distance, the same stiffening and the same release. The pitch is orthographic: it foreshortens the ground evenly without pulling trees or buildings towards a central vanishing point, while close-terrain elevation rises off the sheet and exposes real sides. The eye drops exactly as far as the map turns — one limit for both, because it is one gesture, and a map that leaned a third further than it could be turned read as two separate controls. Dragging back up lays it flat again.

The map image, its procedural cloudy pixel noise, and the region and road names written on it are all drawn through one matrix, so they turn and lean together as one sheet — those names are ink on the paper and lean with it. The noise is generated once from several seamless scales rather than read from LOTR's paper overlay, repeats without an edge, and uses native map-image coordinates so broad patches and fine grain grow and shrink with the underlying map instead of stretching across the whole world texture or remaining camera-sized. It is blended as a quiet texture rather than a heavy recolouring pass. Road names used to be drawn in screen space with the map's turn undone by hand, which kept the letters level but let a name swim away from the road under it the moment the map was tilted; they are now on the sheet with everything else, and stay on their road at any angle. What is pinned to a place rather than painted on it stays upright and readable: markers, their names, their hover cards and the fast-travel popup. Panning, zooming, marker placement, hit testing and grouping all use the same transform and its exact inverse, so what is under the pointer is what responds. The compass rose sits above the control strip and turns with the map, so it always shows where north now lies. Closing the map returns it to square.

At the closest zooms, the printed map cross-fades into a simplified relief view of terrain the client already has loaded. Height, block material, buildings, trees, and other changes therefore come from the connected world rather than from the printed map. The mesh reuses Minecraft's existing block texture atlas and adds directional top and side shading; it does not create a second live world camera. Markers, labels, hover states, tooltips, the compass, and controls keep their normal ordering above it, and terrain depth is discarded before those UI passes begin. Unknown and not-yet-prepared tiles retain the printed map; opening the GUI does not request, load, or generate chunks. Cheap chunk-existence candidates are scanned separately from the four-snapshot tick budget, and unchanged refreshes retain their existing GPU mesh. Preparation and uploads remain incremental, limited to two bounded LOD meshes per frame, and the available maximum zoom uses 3-by-3-block surface cells rather than full block geometry. Elastic zoom cannot switch that LOD and edge cells are clamped to their owning chunk, preventing rebuild waves and overlapping depth geometry. GUI-space elevation is bounded separately from horizontal zoom, retaining visible hills and structures without letting tilted relief expand the off-screen draw set. The dimension-specific session cache holds at most 2048 client-known chunks, captures a circular region at most 33 chunks across around the player, and can retain older visited terrain until least-recently-used eviction. The two transition zooms are client settings in `losttales.cfg`.

Two kinds of thing are drawn onto the map itself, and they are drawn in opposite ways.

Clouds hang above it. A bank of cloud sits over a fixed stretch of Middle-earth and is measured in it, so the zoom grows and shrinks the sky exactly as it grows and shrinks the ground beneath — and because the clouds are between you and the map, panning carries them slightly further than it carries the ground. The restrained parallax matches their low altitude. Lean the map and they stand just above the country they are shading instead of lying on it, with a subtle map-aligned shadow remaining on the actual ground footprint below; rain converges on that same footprint. The cloud itself faces the reader, like everything else standing over the map. Where the banks are is a hash of the map position run through a broad, slowly varying field, so the sky has crowded country, thin country and clear country rather than an even scatter, and the same country is under the same weather on every client with nothing sent about it. The sky drifts slowly westward over the ground. Fair-weather clouds are white and thin enough to read the map through; while it rains or thunders, the same clouds darken one by one as the weather strengthens, so a front reads as the sky thickening rather than as the whole map changing colour.

Decorations stand on it: waves on open water, trees in the forests, peaks on the mountain ranges, ships on the coasts and navigable rivers, and travellers walking the roads. Each one covers a patch of Middle-earth of a certain size and keeps it, so pushing the map closer makes it larger exactly as it makes the ground larger, and pulling the map out makes it smaller until it is too small to say anything and is dropped. Only its base is a map position: the sprite is then drawn upright and square to the screen, so it always faces the reader. Orthographic pitch keeps equal features the same size anywhere on the map instead of leaning or shrinking them towards the middle of the screen.

Placement is a hash of the map position, so a coastline has the same waves on it every time and every client sees the same ones, with nothing sent about it. Where each kind belongs is read from LOTR's own biome image rather than guessed: water, forest and mountain are asked of the map data directly, and two rings of samples around each candidate reject ponds, single tiles and rivers, so a wave needs open sea and a tree needs real forest rather than one stray pixel of it. Within the ground that qualifies, every kind clumps — a slowly varying field of the map position gives each of them dense cores, loose edges and stretches with nothing in them, at the scale that suits what it is, so a wood is not an even dotting of trees and a range is not an even dotting of peaks. Ships ask the opposite question of the water — water with a shore in sight — so they keep to coasts, and because a river is thin enough to be mostly bank and a lake small enough to be mostly shore, the same test puts them on both without a rule of its own. Belegaer is not empty of sail, but very nearly: a second, far sparser rule places the occasional lone ship out in the deep, where the first one cannot reach. Some of them sail: a ship stands out from its mooring and comes back on a slow swell of its own, worked out from the world clock so it is in the same place on every client, and only where the water is open enough along its heading for the whole run — a ship never crosses land. Travellers are a position along a road worked out from the same clock, and only roads long enough to be highways carry any at all, so meeting one is worth noticing.

Trees do not sway and never did anything else: the two drawings in that sheet are variants to choose between rather than frames to step through, because a wood where every tree moved in step read as the paper rippling. Every kind draws further variety from what it already has — a size of each site's own and half of them turned round — so neighbouring copies of one drawing do not read as one stamp repeated.

Zoom is not an input to any of this. Where every decoration of a kind stands is worked out once for the world — a slice of the map per frame, so opening the map costs nothing and the last of it settles within about a second — and from then on the map draws all of them. A decoration is drawn at whatever size the ground under it is drawn at, and it stops being drawn at the point where it is down to about a pixel and there is nothing left of it to see. Nothing fades, nothing is thinned away to save work, and pulling the map out and pushing it back in gives the same country back rather than a different scatter that faded in on the way.

Tilt the map and each one lays a shadow of its own artwork down on the ground beside it, always to the right. It is not a shadow cast by a light somewhere off the map: a light has to pick a compass direction, and a compass direction swings round with the country every time the map is turned, so the shadows would walk about the sprites. It is the sprite itself folded flat onto the country, which is why it is only there while the map is tilted — looking straight down at something standing up, there is none of it lying on the ground to see, and as the eye drops more and more of it is. The fold is laid out on the sheet, so it squashes towards the horizon with the country it lies on while the sprite above it stays upright, and that difference between the two is most of what makes a tree look like it is standing there.

Tall things stand up as the map tips, too: a mountain is drawn a little taller as the eye drops, its foot pinned exactly where the ground is. That is a vertical scale of a square-on sprite and nothing else — no shear, no rotation, no resampling along a diagonal — so pixel art stays pixel art. Markers are left out of both: they are pins in the paper rather than things standing on the country, and lifting one off the place it marks reads as the pin coming loose.

While the map is open it draws its own pixel-art pointer and hides the system one. The pointer's tip is the exact coordinate every hit test is resolved against, so what you aim at is what responds at any resolution or GUI scale. It has two poses: an arrow over anything that does nothing, and a pointing hand over anything a click would reach — a button, a marker or waypoint, a legend tile, a popup action, or an inventory slot on the other screens that use the same pointer. The hand is decided by the same hit tests the click itself runs, in the same order, so the pointer cannot promise something the click would not do; a popup owns the pointer alone while it is open, exactly as it owns the click. The system pointer is restored when the map closes, when another screen takes over, and on the tick after anything goes wrong inside the map screen.

Press `R` on the map to bring the camera back to where you are standing, and `F` to open Find Location: type part of a name and pick a place from the list to fly the camera to it. The list holds only what the player is allowed to be told about — places they have found, their own and shared waypoints, and their party's markers — so a location that has not been discovered cannot be found by name either.

The control strip names every map input as a key icon with a label, including the operator teleport key when the player is an operator; LOTR's own "Press 'M' to /tp" subtitle is filtered out so the action is named once rather than twice in two styles. The biome label, coordinates, and compass rose move with this strip during its delayed entrance instead of moving with the map behind it. The character-menu and quest-journal bindings remain active while the map is open, and every Lost Tales map entry point passes through the same LOTR map replacement path so opening it from `M`, the character menu, the waystone screen, or LOTR's menu produces the same screen behavior. The fullscreen map drops LOTR's fullscreen, zoom-in, zoom-out, create-waypoint and sepia widgets: the map is always fullscreen here, zooming is continuous and driven by the mouse wheel, waypoints are created from the Lost Tales popup instead, and the map has one look rather than a control that changes it wholesale. Only the button is dropped — LOTR's own sepia setting still decides, and when it is on, marker icons and their labels are converted through the same sepia the map image is, so they belong to the picture instead of sitting on top of it in full colour.

Roads, marker icons and marker names fade out as the map is pulled out, all three on one rule. They remain fully visible through the first 75 percent of the journey from maximum zoom-in to maximum zoom-out, fade smoothly between 75 and 99 percent, and remain fully hidden through the final 1 percent. The thresholds follow the configured zoom range rather than becoming stale when either limit changes. A name fades exactly as its icon does. What can be clicked follows what can be seen: once a marker is down to a few percent of a colour it stops owning hover, tooltips and clicks, so the map never catches on something that is not there.

Press `C` on the map to create a personal waypoint; the map's control strip shows the binding. The popup takes a name, an optional description and an icon colour, then hands the name to LOTR's own create-waypoint request, so LOTR still places the waypoint at the player's position and still enforces its name rules and per-player limit. Clicking one of your own waypoints reopens that popup as its editor: rename it, recolour it, change its description, travel to it, delete it, or toggle which of your fellowships it is shared with. The editor works on the name you typed rather than the "(Custom)" one LOTR displays, which is also the key the colour and description are stored under — editing under the displayed name saved both somewhere nothing read. Renaming, deleting and sharing all go through LOTR's own requests, so ownership and permissions are enforced by the server exactly as before, and the share rows always show LOTR's own state. A waypoint shared with you by someone else opens the ordinary fast-travel popup instead, because it is not yours to change. Personal and shared waypoints are drawn with the Lost Tales personal marker icon and are labelled `Personal:` or `Shared:` rather than carrying a "(Custom)" suffix. The colour and description are client-side presentation only: they are stored in `customWaypointColors` and `customWaypointNotes` in the Lost Tales config, keyed by the waypoint's own name, and are never sent to the server or to other players.

A place is called whatever the bundled marker definition calls it, on the map and on the compass alike, so the two can never disagree about the same location. The names of markers mapped onto LOTR waypoints are the names LOTR itself uses, because that is what is written in those files.

A location that has not been discovered yet keeps its position and gives up everything else: a question mark on the map, a hover card that says only that it has not been found, and a travel popup that names it no more precisely. One rule decides that for all three, so the name and description cannot leak through whichever of them is drawn.

Clicking an eligible destination — a map marker or a LOTR waypoint — opens the fast-travel confirmation. Standing at a waystone travels through the waystone; otherwise the request goes through LOTR's own fast travel. A destination that cannot be used right now still opens the popup with the reason on it. Discovery, region unlocks, cooldowns and destination safety are re-checked on the server for every request, whichever route it took.

With the popup open, the left and right arrow keys, `A` and `D`, and the arrows beside the panel move it to a nearby destination without closing it: the camera runs on to the new place, the highlight follows, and the question is asked again about it. The order is worked out once, when the popup opens — nearest to where you clicked first, with equal distances settled by the destination itself so it cannot reshuffle between frames — and it wraps at both ends. Only destinations you could have clicked take part, decided by the same discovery, visibility, filter and eligibility rules the map already draws them by, and each is checked again as it is stepped onto, so a place that has been filtered out or deleted while the popup was open is stepped over rather than shown. A destination with nowhere else to go shows no arrows and does not answer their keys.

`/losttales mapmarker` provides permission-level-2 tools to inspect, discover, forget, track, or untrack markers for testing and administration.

## Quick loot

Quick loot works only for supported inventories in reach. The client requests a preview; the server re-resolves the block, distance, inventory, seal state, dimension, and slot before any mutation. A stale or fabricated slot request is ignored. Sealed urns can be displayed but cannot be emptied through quick loot.

The feature drops the selected full stack into the world above the container. It does not transfer items directly into the player's inventory.

## Key icons

The same animated key artwork the quick-loot and map control strips use is also drawn inside item tooltips, so a hint reads "Hold [icon] to view item lore" rather than naming the key in text. Tooltips are a list of strings and nothing else, so the icon travels inside one as a marked span carrying both the key it stands for and the plain label it replaces; the coremod offers every tooltip to Lost Tales before vanilla draws it, and only the ones carrying a marker are taken over — everything else is drawn by vanilla exactly as before. The line an icon sits on is measured and drawn taller than a line of text, and the box grows with it, because measurement and drawing happen in the same pass. Nothing writes a marker until the tooltip renderer is patched, so on an installation where that patch does not apply the hints simply name their keys in text, and a foreign tooltip renderer that never learned about the markers still shows the readable label.

## Third-person camera and combat

The optional third-person overhaul provides profile-based camera distance and offsets for standing, moving, sprinting, sneaking, swimming, riding, combat, aiming, and attacking. It includes smoothing, motion effects, shoulder switching, zoom, block collision, FOV changes, directional movement, target lock, camera-intent actions, and a projectile trajectory guide for compatible vanilla and LOTR weapons.

Target lock and trajectory rendering are client aids. Entity attacks, interactions, block actions, and ranged charge bonuses are checked again on the server for distance, line of sight, current item, timing, player state, target validity, and request rate.

After a compatible weapon reaches its normal full draw, the default server charge tiers begin at 10, 24, and 42 additional ticks. Their default damage multipliers are 1.12, 1.30, and 1.60. Their default velocity multipliers are 1.04, 1.09, and 1.16. Servers can disable or tune the system.

If a camera transformer does not match the installed game or dependency bytecode, the affected path falls back to vanilla behavior and logs a warning.
